# C4 first-use program warmup candidate

The new Windows C3 profile attributes 212.735 ms of a 226.455 ms first-use submission to two shader initialization waits. C4 prepares the measured non-tiled, unclipped opaque HD sprite body/coverage pair during the existing single-player loading stage, using the actual scene's lighting and render configuration. It retains only two material owners through that scene's lifetime so later native batches can acquire the same programs. C1/C2/C3 rendering changes remain exact; main stays at frozen d38f136 and M2.3 remains independent.

`HdSpriteProgramWarmup` creates one detached single-item merged mesh from the production material/batch path. Its textures are borrowed from an already loaded RGBA HD material; it loads no family, holds no extra texture lease, never joins the world tree and submits no draw. Original indexed coverage does not activate this warmup. The asynchronous compile is followed by the normal first-use uniform/error initialization while the loading screen is still active. Error checks remain enabled, including platforms without parallel compilation. Exit, renderer disposal, context restoration and preparation failure release owners without disposing borrowed textures. Loading can take longer; this intentionally moves the measured wait before play. Context restoration, different shader variants and initial native simulation costs remain separate limitations.

The focused change is limited to `Renderer.ts`, the new helper and loading cleanup in `GameScreen.ts`. Preparation precedes scene attachment; cancellation therefore uses the existing loading token, and the screen's disposal also releases prepared owners before attachment or after a later startup failure. Quality, resources, fixed budgets, native game ticks, explicit scene/post-batch matrices, fallback and shadow behavior are unchanged.
