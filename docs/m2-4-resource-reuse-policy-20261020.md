# M2.4 accepted resource reuse

Check accepted material before requesting new artwork. Exact source-byte, canvas or palette-index equality is sufficient for reuse; it is not necessary. Batch 91 corrects an overly strict eligibility check that would otherwise redraw accepted hospitals, airports, oil machinery and rubble. Its evidence and implementation are in `m2-4-newurban-accepted-reuse-batch91-20261020.md` and the corresponding artifact directory.

Compare actual native geometry and rendered semantics. SHP positions use the trim origin minus the floored source-canvas center, plus the unchanged Art offset. Different transparent margins can therefore produce identical geometry. A target header can register accepted pixels without copying donor canvas, collision, shadow, map or rule data. Keep target source SHA, native logical canvas, trims, frame order, role, palette and source provenance authoritative.

Distinguish structure, ownership, contact semantics and material variation. Different indexed palettes may encode nearly identical colors, lighting and debris structure. Record the original masks, RGB differences, material statistics and native context rather than treating index differences as automatic new-art requirements. Correlation alone is not proof of compatibility: inspect defining features, states and complete family composition. Preserve meaningful environment-specific material, snow cover, native depth, bridge/shore contacts and object restrictions. In TMP reuse, confirm tile/subtile order, block and extra geometry, ownership and depth before adapting color. Do not fill placeholder resources or invent missing tiles.

Use accepted RGB/alpha/auxiliary data directly where compatible. A narrowly bounded owner, contact, palette or registration adapter should identify the target source, exact changed cells/channels and retained donor. Quantization flecks and tiny raster holes do not justify redrawing unchanged architecture or reintroducing low-resolution grain. Native index 12 means different things in Unit and Iso contexts; determine the actual palette role before treating it as a shadow. A whole source family, including linked states and original empty slots, must remain complete.

An accepted-art reuse must not be presented as newly generated HD detail or as exact original-source equality when that equality is absent. Preserve the old artwork acceptance authority. Validate changed bindings and representative affected native states, using actual source-map membership to choose cases. Reuse unchanged full-loop, garrison and actor-matrix evidence. Keep Mac technical status, inherited artwork acceptance, new art review, Windows status and main integration separate. Request a new art decision only for actual new or changed artwork, grouping it to reduce review frequency.

Keep every selected payload, target/donor source, adapter, dependency and recovery pin reviewable. Unused generated mothers and superseded candidates remain explicitly unselected. Prepared data must follow real changed inputs. Check allocation on affected maps without increasing budgets or removing expected resources. Use the isolated task selection and shared internal Mac validation host; per-batch Desktop delivery remains embedded HTML and metadata, without another game or resource copy.
