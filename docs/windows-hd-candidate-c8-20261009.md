# C8: avoid forced matrices from the static actor container

The validated C7 M1 Windows return captures a later manual F8 interval at 21.35 mean loop FPS. Its normal scene-update/submission medians are 17.525/19.345 ms, with 1,420 median draw calls. A separate trace identifies sustained renderer-thread CPU work and world-matrix traversal, with no new shader compilation/linking. See `windows-hd-c7-manual-windows-results-20261009.md` and its JSON for provenance, instrumentation limits and the preserved raw return.

C8 changes one application path, `src/engine/gfx/OctreeContainer.ts`, above C7. The identity wrapper no longer recomposes its unchanged local transform each frame. Previously, Three's `updateMatrix()` marked this wrapper dirty and forced descendant world-matrix multiplication during every explicit world pass. Descendants retain their own automatic/dirty flags; native movement, joint animation, parent changes and new actors still update. The explicit translated scene-root pass, UI pass, post-batch update, native shadow/picking geometry and cached heading ownership remain intact.

A copied immutable C7 Mac runtime confirms the mechanism at native tick 9,571 with eight combatants/seven AI and 7,573 actor-subtree nodes. Changing only the wrapper flag reduces update-time matrix products from 11,822 to 4,747 at the manual camera and 11,805 to 4,745 at two other cameras. Every stored node's world matrix is identical. Two frozen A/B/B/A samples per camera have scene-update medians of 10.42/10.905 ms versus 8.625/8.675 ms at the manual camera; the other cameras also improve. These are Mac frozen controls, not Windows gameplay FPS or a promise of high-refresh output.

The new regression first fails on C7's unnecessary static-child multiplication, then passes with C8. It also verifies movement, recoil, automatic descendants, newborn/reparented children and translated scene roots. All 15 focused/shared tests (149 assertions) and entry type checking pass.
