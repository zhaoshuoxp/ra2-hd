# Desktop icon and bilingual project overview

The README presents the implemented project in Chinese and English, with matching scope, HD coverage, platform information and attribution. It contains no milestone chronology. Chinese documentation is explicitly authorized for this README.

The application icon follows the user's combined reference: a complete Yuri emblem at the upper left and the RA2 hammer-and-sickle star at the lower right, closely arranged on a rounded rectangular tile. The final requested background is neutral dark graphite; the emblems retain their original colors. Earlier shield and single-emblem candidates were rejected and are not packaged. The generated master, final PNG, ICNS, ICO and exact built-in image-generation prompts are in `desktop/icons/`.

`scripts/distribution/build-icons.py` performs only container conversion and resizing. The Mac ICNS includes 16 through 1024-pixel representations; the Windows ICO includes seven sizes from 16 through 256 pixels. Run the native macOS converter outside the restricted sandbox if `iconutil` reports an invalid icon set for otherwise valid PNGs. Both initial sandbox attempts failed; conversion succeeded with the same source outside that sandbox.

Distribution packaging installs the ICNS through `CFBundleIconFile`, sets the Mac Dock icon and the Windows window icon, and embeds the ICO in the Windows executable. The pinned build-only `resedit` dependency updates PE icon resources. The resulting executable is unsigned; no publisher-signature claim is made. Code/data section hashes and non-icon resources are preserved. A larger resource section moves the following relocation table; its contents remain identical and its PE directory pointer is verified. An initial overly strict address comparison rejected this expected relocation before writing the executable.

The update reuses the accepted renderer and gameplay payload. All 237 prior application files outside the distribution bootstrap and metadata remain byte-identical, and all 13,978 game-resource hashes are preserved. Existing shared resource ZIP parts are verified and reused; the four platform program/full ZIPs and the standalone Mac application receive the new icon. User settings are excluded and untouched.

Two distribution-layout tests pass. Native Mac checks launch the complete application's YR menu and the program-only application's RA2 menu using isolated profiles, decode the 1024-pixel icon, confirm Dock visibility and observe no page errors. The test applications close afterward. Initial diagnostic attempts failed on unsupported dynamic import in the automation evaluator and on process closure during `app.getFileIcon`; the final check uses direct image decoding plus bundle/signature validation. These are recorded harness limitations, not evidence of Windows behavior or a new gameplay/artwork acceptance matrix.

Windows validation checks executable structure and embedded icon bytes on the Mac; native Windows launch and Explorer/taskbar appearance remain untested. Package checks and exact delivery hashes are retained under `../project-history/desktop-icon-20261022/` after delivery. This update does not create a public Release or upload to Google Drive.
