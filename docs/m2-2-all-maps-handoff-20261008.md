## Windows performance remains an open issue

The user reports an 8 GB Windows GPU, smooth play with HD Off, and substantially more stutter at 4X than 2X. This is new user-supplied evidence; this Mac host has not executed the new Windows package. It must not be relabeled fixed by raising the 2X ceiling.

The project ceiling is not a measurement of total dedicated VRAM. Terrain/environment accounting includes retained CPU data, while some existing actors report GPU allocation. Native textures, geometry buffers, framebuffers and driver allocation are additional. A larger admission ceiling prevents avoidable Original fallback; it can also increase the amount of active HD work. At equal logical area, 4X has four times the texture pixels of 2X. Windows needs matched Original/2X/4X measurements of steady frame cost and p95/p99/max stalls, actual GPU residency, uploads and first-use shader work before choosing another increase. Windows assigns a per-process memory budget; exceeding it can cause paging and stutter: [Microsoft DXGI memory budget documentation](https://learn.microsoft.com/en-us/windows/win32/api/dxgi1_4/ns-dxgi1_4-dxgi_query_video_memory_info).

`docs/windows-scene-performance-20261006.md` records the prior matrix-traversal repair already inherited here. It also retains a Windows `getProgramInfoLog`/first-use shader concern and explicitly does not close all stalls. Do not reintroduce duplicate world/UI matrix traversals or attached unused coverage meshes. Prior Mac 60 Hz samples are not Windows evidence. A future 2 GiB 4X experiment on the 8 GB machine should be a measured comparison, not a claim that more memory cures the current slowdown.
