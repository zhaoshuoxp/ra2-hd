## Diagnostic design

`WINHD-20261008-D38F136-A1` is an opt-in portable Windows x64 kit. Its launcher selects a small American Town/one-AI scene or the retained xmp27t8/eight-player/seven-AI stress setup, then Original/2X/4X. Setup, fixed timestamp, logical viewport, native speed, shadows, model quality and camera route remain fixed within each scene. Fresh-process first use, warmed steady play, native `reset` re-entry and warmed re-entry produce bounded raw frame rows and exact realized configuration. The smaller scene is a candidate reproducer until the Windows user confirms it. The stress case remains available.

Small requests a 1280x800 DIP window; stress uses native fullscreen on the current display. Both retain the accepted logical presentation height of 900, independent of density and framebuffer resolution. Realized window, logical view, output and DPI are recorded. The short root instructions link to the read-only complete protocol in `Reference/TEST-PROTOCOL.txt`.

The diagnostic entry dispatches to the original portable entry when its explicit environment flag is absent. Production main/gameplay source and matrix/inactive-layer repairs remain unchanged. Profiles are unique and excluded from return ZIPs. No TCP debugging listener is opened: the short profiler uses Electron's in-process WebContents debugger, detached after capture. Export reads only an explicit evidence allowlist and refuses links, identity mismatches, path traversal and overwrite. Return files include raw samples, summaries, machine/backend/display/power data, phase-boundary Electron process metrics, errors, exact manifest and current launchers. Optional run-local user notes provide perceived smoothness and reproduction steps.

The renderer probe reuses the existing debug references, HD reports, preparation/cache statistics and normal renderer/tick methods. It collects raw frame intervals plus separate CPU tick, renderer-update and render-submission costs in memory, with boundary-only disk writes. Scene graph counts, actual HD bindings/fallbacks, program count and allocation snapshots are collected at boundaries. The separate heavy phase captures an eight-second CPU/multiprocess trace, material changes and CPU WebGL method counts/durations for shader compilation, linking, program-log retrieval, program switches and upload calls. F9 can capture initial first use; overlapping and later phases in that process remain labeled instrumented. It contains no synchronous GPU readback or `gl.finish`. Available trace categories are queried from the installed runtime rather than assumed. Serialized atomic report writes publish completion only after evidence is flushed.

Actual GPU time, per-process GPU memory/budgets, upload byte volume and unavailable queue/decode CPU timings are explicitly `UNAVAILABLE`. App allocation reports and Three object counts are not VRAM measurements. WMI adapter RAM is raw potentially truncated metadata; Electron's actual active adapter/backend/feature status and driver details must be inspected. Worker `workerMs` is elapsed request round-trip time. Electron memory uses documented KiB fields by PID/type, including renderer/GPU processes. Native symbols are not included; unresolved native stacks remain unresolved.

The kit includes complete hash-verified retained R10 sibling resources, read-only relevant source and both lockfiles, installed version/API material, selected reports and exact rebuilt diagnostic JS/hidden maps. The reference snapshot is not an immediately buildable checkout and Windows requires no development dependencies. The frozen source is rebuilt into an isolated output to generate matching maps; rebuilt bundle hashes are independently recorded rather than inherited from R10. Original packages, `dist`, profiles and peer worktrees remain intact.

APIs are checked against installed Electron declarations and Three implementation plus the official [Electron tracing](https://www.electronjs.org/docs/latest/api/content-tracing), [app metrics/GPU APIs](https://www.electronjs.org/docs/latest/api/app) and [WebContents debugger](https://www.electronjs.org/docs/latest/api/web-contents) references.
