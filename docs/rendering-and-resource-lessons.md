## TMP environment authoring

Paint and fit complete native structural assemblies before cutting subtiles. Repainting one road-edge subtile across all slots duplicates curbs; preserving a source contract does not prove that the assembled artwork is correct. Retain native TMP zero-offset slots and decoder behavior explicitly. [M2.1 representative evidence](m2-1-temperate-environment.md).

Ground clarity must come from authored form and readable material scale. Source interpolation with microtexture failed the user's clarity review. Diamond-cropped material masters introduced repeated borders; continuous full-bleed fields and measured periodic-boundary correction removed that authoring artifact. Fill transparent guide RGB before filtering and preserve native alpha independently.

Terrain atlas GPU, retained CPU and validation buffers share the existing world cap. Keep native geometry, lighting, picking, shroud and overlays independent of texture density. Admit complete declared groups by resolved source identity; retain native fallback for failed groups and Original controls outside the bounded preview.

Actual game display size can differ from framebuffer dimensions. Match the recorded CSS renderer size by default and label optional pixel inspection. Apply HTML template substitutions in one pass before inserting base64 media. Verify every embedded image/video byte and play every clip to completion; an unindexed MediaRecorder duration or a partially parsed page can otherwise produce misleading checks.

Map-wide environment inventory must parse actual edition rules and map overrides before resolving art. Compare placed records as multisets to separate array-order differences from changed identities: the RA2/YR showcase differs by hospital rules identity, one ore overlay and a waypoint, despite matching terrain cells. Include normal-play ore amount/growth and bridge damage/repair family ranges; an unregistered endpoint is not a missing renderable object. See [M2.2 coverage and direction review](m2-2-temperate-showcase.md).

Invented shore-land bevels require complete reusable group correction and overlapping whole-map inspection. Register bounded authored fine detail against native land color while protecting accepted water, enclosed warm islands and a native-pixel guard. Bridge asphalt masks must include cool native contact shades; match adjoining roads using actual framebuffer measurements. A produced family is distinct from a visible runtime binding: invisible bridge placeholders and unreachable range members must remain explicit. Preserve the frozen inventory and add a final resolution rather than relabeling its original missing counts. See [R7 feedback](m2-2-feedback-r7.md) and [final acceptance](m2-2-final-acceptance-20261007.json).

Use the existing building animation helpers for dependency closure. Building child animations inherit the parent palette in the runtime; their damaged-art parameters and shadow/offset/reverse semantics still need separate metadata. Native SHP index buffers, empty slots and VXL HVA/VPL provenance are immutable authoring inputs. A high-resolution representative board selects a direction but does not supply adequate resolution for every large 4X structure. Export each density directly from an adequately sized master, label single-slot pilots accurately and retain raw internally rejected studies. Direction approval, complete resource publication and in-game state acceptance are separate gates.

## Evidence reuse and rerun triggers

Documentation, relocation indexes and byte-identical resource copies reuse existing native acceptance. Reverify exact copied bytes, containment and dependency closure after relocation. A catalog change requires selected source/resource and edition checks; a decoder, compact-data, pooling or storage change requires affected prepared-byte equivalence and regeneration if different. Shared renderer changes require affected animation, shadow, owner, arc and teardown checks in the actual copied app. Changes to deployment/cooldown logic require native idle, post-control, repeat, cancellation and recovery cases. Current resource caps are 128 MiB prepared CPU, 512/1280 MiB world at 2X/4X and independent 16 MiB UI; the R10-authorized 2X increase supersedes the historical 256 MiB limit.

- Report matched loading, update/render cost, frame tails and process memory independently. Short Mac measurements, retained CPU/texture charges and user visual acceptance do not establish Windows performance, physical VRAM use or long-duration stability.
